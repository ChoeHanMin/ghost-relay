# 고스트 릴레이 (GHOST RELAY) — 제작 설명서

> 이 문서 하나만 읽고 게임을 처음부터 끝까지 만들 수 있게 쓴 설명서입니다.
> 대상: 이 게임을 구현할 Claude Code 세션 (그리고 팀원).
> 출품처: 2026 saaskr 게임 어워드 (game.saaskr.com) — 후보 마감 2026.12.20, 결선 투표 ~12.31.

## 0. 한 문단 요약

30초 동안 자동으로 달리는 캐릭터를 **버튼 하나(탭·길게 누르기)**로 점프시키는 횡스크롤 러너.
한 판이 끝나면 내 입력 기록이 **"도전 코드"**가 되고, 친구가 그 코드를 넣으면 **앞사람들의 반투명 유령과 같은 맵을 함께** 달린다.
친구가 끝내면 유령이 하나 늘어난 새 코드가 나오고, 이렇게 이어서 **최대 10명**이 한 화면에서 달리면 릴레이 완주.
서버 없이 **HTML 파일 하나**로 동작한다.

## 2. 플레이 방법 (플레이어 입장)

### 2-1. 기본 조작
- **탭(짧게 누르기)**: 낮은 점프
- **길게 누르기**: 누르고 있는 동안 더 높이 뜀 (최대 약 0.2초까지 높이 증가)
- 공중에서는 다시 점프 불가 (2단 점프 없음)
- PC: 스페이스바 / 위쪽 화살표 / 마우스 클릭 모두 같은 버튼
- 캐릭터는 자동으로 오른쪽으로 달리고, 속도는 시간이 갈수록 조금씩 빨라짐

### 2-2. 한 판의 목표
- 30초 동안 최대한 멀리, 별을 많이 먹으며 달리기
- 장애물에 부딪히면 **죽지 않고 0.75초 멈칫** (그만큼 거리 손해)
- 구멍에 빠지면 **1초 뒤 구멍 건너편에서 다시 시작** (더 큰 손해)
- 30초가 끝나면 무조건 종료 → 모두가 같은 시간을 달리므로 유령들이 끝까지 화면에 남음

### 2-3. 점수
```
점수 = 거리(m) + 별 × 5 + 싱크 × 3 + 구조 × 10
```
- **거리**: 16px = 1m. 보통 실력이면 30초에 250~300m
- **별**: 공중·바닥에 있는 연두 별. 1개 5점
- **싱크**: 유령이 점프를 누른 순간과 ±4틱(약 0.07초) 안에 나도 점프를 누르면 +3점. 유령 점프 하나당 한 번만 인정. "싱크!" 팝업
- **구조**: 앞의 유령 **아무도** 못 먹은 별을 내가 먹으면 별 점수에 더해 +10점. "구조!" 팝업
- 순위는 **점수** 기준. 동점이면 거리 → 먼저 달린 사람 순

### 2-4. 릴레이 진행
1. A가 "새 릴레이 시작" → 혼자(+연습 유령) 달림 → 코드 A 생성
2. A가 카카오톡 등으로 코드 A를 B에게 보냄
3. B가 "도전 코드 넣기"에 붙여넣기 → A 유령과 함께 달림 → 코드 A+B 생성
4. … 반복. 코드 하나에 유령은 최대 9명 → 10번째 주자가 달리면 **릴레이 완주**
5. 완주된 코드는 더 이상 주자를 받지 않고 "완주 기록 보기(다시보기)"만 가능. 대신 "같은 맵으로 새 릴레이" 버튼 제공

### 2-5. 맵 종류
- **오늘의 맵**: 날짜(한국 시간 기준 YYYYMMDD)로 시드를 만든 맵. 매일 바뀜 → 매일 다시 올 이유
- **자유 맵**: 무작위 시드
- 릴레이 코드에는 시드가 들어 있으므로, 날짜가 바뀌어도 친구는 **같은 맵**을 달림

## 3. 화면 구성과 흐름

```
[타이틀] ─ 새 릴레이 시작 ─→ [닉네임(처음 1회)] → [카운트다운] → [플레이] → [결과]
    │                                                                     │
    ├─ 도전 코드 넣기 → [코드 입력·미리보기] → [카운트다운] → [플레이] → [결과]
    ├─ 하는 법 → [하는 법]                                                │
    └─ 소리 켜기/끄기                                  다시 달리기 / 코드 복사 / 타이틀
```

### 3-1. 타이틀
- 로고 "GHOST RELAY" + "고스트 릴레이"
- 배경: 캐릭터가 달리고 유령 3명이 따라오는 데모 애니메이션 (실제 시뮬레이션 재생)
- 버튼: **새 릴레이 시작**(연두 채움) / **도전 코드 넣기**(테두리)
- 작은 배지: "오늘의 맵 · {맵 이름}" (맵 이름은 시드로 정한 형용사+장소, 예: "네온 골목", "젖은 옥상")
- 작은 글씨: "내 최고 점수 312" (localStorage 있을 때만)
- 구석: 하는 법(?) 아이콘, 소리 아이콘
- "새 릴레이 시작"을 누르면 작은 선택: **오늘의 맵**(기본) / 자유 맵

### 3-2. 닉네임
- 처음 한 번만. 1~6글자, 한글·영문·숫자. 기본값 "러너" + 랜덤 숫자 2자리
- 안내: "실명·학교·전화번호는 쓰지 마세요"
- 저장(가능할 때만), 결과 화면에서 바꿀 수 있음

### 3-3. 도전 코드 넣기
- 큰 입력칸(textarea). 붙여넣기 버튼(클립보드 읽기 가능할 때만 표시)
- 입력 즉시 해석 → 미리보기 카드:
  - "릴레이 #A7F2 · 주자 4명 / 10 · 맵: 네온 골목"
  - 유령 목록: 닉네임 + 점수(코드 안 입력으로 **직접 재생해서 계산한 값**), 1등 왕관
  - 10칸 진행 막대 + "다음 주자: 나"
- 오류 안내 (구체적으로): "코드가 잘렸어요(끝부분 확인)", "고스트 릴레이 코드가 아니에요", "이 코드는 이미 완주됐어요 → 다시보기 / 같은 맵으로 새 릴레이"
- 공유 문구째 붙여넣어도 동작: 텍스트에서 `GR1.` 로 시작하는 부분만 자동 추출
- 버튼: **유령들과 출발**

### 3-4. 카운트다운
- 출발선에 나 + 유령들이 겹쳐 서 있음, 닉네임 태그
- 3 · 2 · 1 · GO (각 0.6초, 효과음)
- 상단 "주자 5 / 10 · 네온 골목", 하단 "탭: 점프 · 길게: 높이 점프"
- 카운트다운 중 입력은 무시 (기록 시작은 GO부터)

### 3-5. 플레이
- 상단 HUD: 남은 시간 `00:18` / 점수 / 유령 수
- HUD 아래 얇은 진행 막대: 내 위치(연두 점), 유령 위치(시안 점), 1등 유령(금색 점)
- 내 캐릭터: 화면 왼쪽에서 약 1/4 지점 고정, 월드가 스크롤
- 유령: 반투명 시안, 각자 모자 색 다름, 잔상 2~3개, 머리 위 닉네임 태그. 화면 밖 유령은 화면 가장자리에 화살표+닉네임 작게
- 유령이 넘어지면 유령 쪽에 작은 "꽈당" 먼지, 점프하면 작은 점프 이펙트 → 친구의 실수가 보이는 게 재미의 핵심
- 팝업: "싱크! +3", "구조! +10", "별 +5"
- 마지막 5초: 시간 숫자 빨갛게, 박자 효과음
- **일시정지 없음** (30초짜리라 불필요, 결정적 재생에도 유리). 탭 전환 등으로 화면이 숨겨지면 → 그 판은 무효 처리하고 "다시 달리기" 안내

### 3-6. 결과
- "완주!" + "내 점수 233 · 릴레이 5 / 10"
- 순위표 (최대 10줄): 순위, 얼굴 아이콘, 닉네임, 점수. 1등 금색, 나는 연두 강조 + "NEW"
- 칭호 배지(해당하는 것만): "싱크 3회", "구조 2회", "무사고 질주(멈칫 0회)", "역전(유령 1등을 이김)"
- 도전 코드 박스 + 버튼
  - **코드 + 공유 문구 복사** (메인)
  - 코드만 복사
  - 공유하기 (navigator.share 가능할 때만)
- **다시 달리기** (같은 코드·같은 유령으로 다시. 다시 달리면 마지막 기록으로 교체)
- 10칸 릴레이 슬롯 + "10명이 모이면 릴레이 완주!"
- 10번째 주자면: 완주 축하 연출(10명 유령이 한 줄로 뛰는 애니메이션) + "완주 기록 코드" 복사 + "같은 맵으로 새 릴레이"

### 3-7. 하는 법
- 그림 3장 분량: ① 탭/길게 ② 유령과 코드 ③ 점수(싱크·구조·별)
- "친구에게 코드를 보내면, 친구는 내 유령과 함께 달려요"

## 4. 첫 판이 심심하지 않게: 연습 유령(봇)

코드 없이 처음 온 사람도 유령과 함께 달려야 이 게임의 매력이 보인다.

- "새 릴레이 시작" 시 **연습 유령 3명**이 함께 달림: "연습봇 느림", "연습봇 보통", "연습봇 빠름"
- 연습 유령은 **봇이 시드 맵을 직접 플레이해서** 만든 입력 기록 (게임 실행 시 계산, 결정적)
  - 봇 규칙: 앞의 장애물까지 거리를 보고 점프 타이밍 결정 + 실력별 실수 확률(시드 기반 의사난수)
- 연습 유령은 회색 모자 + "BOT" 표시, **코드에는 들어가지 않음**(사람 슬롯을 차지하지 않음)
- 사람 유령이 1명 이상 있는 릴레이에서는 연습 유령을 보여주지 않음
- 봇이 맵을 끝까지 달릴 수 있는지 = 맵이 공정한지 검사하는 도구로도 사용 (11장)

## 5. 게임 시뮬레이션 규격 (결정적 재생의 핵심)

> **가장 중요한 원칙:** 같은 `시드 + 입력 기록`이면 어떤 기기에서도 **완전히 같은 결과**가 나와야 한다.
> 그래서 점수는 코드에 저장하지 않고, 입력을 재생해서 매번 다시 계산한다(조작 방지 효과도 있음).

### 5-1. 시간
- 고정 틱: **60틱/초**, 한 판 = **1800틱**(30초)
- 화면 그리기(requestAnimationFrame)와 시뮬레이션을 분리: 누적 시간만큼 틱을 돌리고, 그리기는 마지막 상태로
- 한 프레임에 최대 5틱까지만 따라잡기 (멈춤 후 폭주 방지)

### 5-2. 숫자는 전부 정수
- 위치·속도는 **고정소수점 정수** (1px = 256 단위). `Math.floor`, 비트 연산으로만 계산
- 시뮬레이션 안에서 `Math.random`, `Date.now`, 실수 나눗셈, `Math.sin` 등 사용 금지
- 의사난수: **mulberry32**(시드 32비트) 같은 정수 기반 PRNG. 맵 생성용·봇용 스트림 분리

### 5-3. 월드 크기와 물리 (초기값, 테스트하며 조정)
| 항목 | 값 |
|---|---|
| 논리 화면 크기 | 가로 256px × 세로 448px (정수배 확대, 픽셀 선명하게) |
| 달리기 영역 | 세로 160~360px 구간, 바닥 y = 320 |
| 캐릭터 화면 위치 | x = 64 |
| 캐릭터 크기 | 12 × 16 (충돌 상자는 10 × 14로 살짝 작게) |
| 시작 속도 | 2.0 px/틱 (=120px/s) |
| 최고 속도 | 3.2 px/틱, 1800틱에 걸쳐 선형 증가 |
| 중력 | 0.25 px/틱² |
| 점프 초기 속도 | -4.2 px/틱 |
| 길게 누르기 | 누르고 있는 동안 최대 12틱까지 중력 0.11로 감소 → 최고 높이 약 2배 |
| 멈칫(장애물) | 45틱 정지 + 깜빡임, 그 장애물은 통과 처리 |
| 구멍 낙하 | 60틱 뒤 구멍 끝 지점 바닥에서 재시작 |
| 거리 → m | 16px = 1m |

### 5-4. 입력 기록 형식
- 한 번의 점프 = `(누른 틱, 누른 길이 틱)` 쌍
- 누른 길이는 0~12로 잘라 저장 (12 넘으면 12)
- 공중에서 누른 입력은 무시하고 **기록도 하지 않음** (재생 시 결과가 같으므로)
- 시뮬레이션은 입력 목록만 받는 순수 함수:
```js
simulate(seed, inputs) → { score, distance, stars, syncs, rescues, stumbles, frames? }
```
- 플레이 중에도 같은 `simulate` 엔진의 한 틱씩 진행하는 버전을 씀 (재생·실플레이 코드가 다르면 반드시 어긋남)

### 5-5. 싱크·구조 판정
- 싱크: 내 점프 누른 틱 t, 어떤 유령의 점프 누른 틱 g에 대해 |t−g| ≤ 4 이면 성립. 유령 점프 하나당 1회
- 구조: 별 하나에 대해 **앞 주자 전원**이 그 별을 못 먹었고 내가 먹으면 성립
- 싱크·구조는 "앞 주자들"에 따라 달라지므로, 각 주자의 점수는 **그 주자가 달릴 당시의 앞 주자들 기준**으로 계산 (코드 안 순서 = 달린 순서)

## 6. 맵 생성

### 6-1. 구조
- 맵 = **패턴 조각**을 이어 붙인 것. 조각 하나 = 폭 160~320px
- 시드로 PRNG를 돌려 조각을 고름. 진행 거리에 따라 난이도 등급 상승
- 전체 길이: 최고 속도로 30초 달려도 끝나지 않게 넉넉히 (약 6000px) 생성

### 6-2. 장애물·아이템
| 이름 | 크기·형태 | 넘는 법 |
|---|---|---|
| 낮은 상자 | 16×16 | 탭 점프 |
| 높은 상자 | 16×32 | 길게 점프 |
| 이중 상자 | 낮은 상자 2개, 간격 40px | 점프 타이밍 |
| 가시 바닥 | 32×8 | 탭 점프 |
| 구멍 | 폭 32~56px | 폭이 넓으면 길게 점프 |
| 네온 간판 | 높은 받침 위 판 | 길게 점프 |
| 별 | 8×8, 바닥 위 또는 점프 궤적 위 | 먹기 |

- 직접 만든 픽셀 모양만. 특정 게임의 선인장·파이프 같은 모양 피하기

### 6-3. 난이도 등급
| 구간 | 조각 |
|---|---|
| 0~5초 | 빈 길, 낮은 상자 1개, 별 줄 |
| 5~15초 | 낮은 상자, 가시, 좁은 구멍, 높은 상자 가끔 |
| 15~25초 | 이중 상자, 넓은 구멍, 높은 상자+별 |
| 25~30초 | 연속 패턴, 공중 별 (피버 느낌) |

### 6-4. 공정성
- 모든 조각은 그 구간 최고 속도에서도 **넘을 수 있게** 설계 (물리값으로 계산 확인)
- 개발 중 테스트: 봇 "완벽" 모드가 시드 1000개에서 멈칫 0회로 완주하는지 자동 검사

### 6-5. 맵 이름

## 7. 도전 코드 형식

### 7-1. 담는 내용
```
버전(1바이트) | 시드(4바이트) | 맵 종류(1바이트: 오늘/자유) | 릴레이 ID(2바이트, 첫 주자가 만들 때 랜덤)
주자 수 N(1바이트, 1~10)
주자 × N:
  닉네임 길이(1바이트) + 닉네임(UTF-8, 최대 18바이트 = 한글 6자)
  모자 색 번호(1바이트)
  점프 수 J(가변 정수)
  점프 × J: 이전 점프와의 틱 차이(가변 정수) + 누른 길이(4비트)
체크섬 CRC-16(2바이트)
```
- 점수는 저장하지 않음 (재생해서 계산)
- 가변 정수 = LEB128(7비트씩). 틱 차이는 대부분 1바이트에 들어감

### 7-2. 문자열로 바꾸기
- 바이트 → **base64url**(`A-Z a-z 0-9 - _`) → 앞에 `GR1.` 접두어
- 화면 표시용으로만 4글자마다 띄어쓰기 가능, 해석할 때는 공백·줄바꿈 제거
- 예상 길이: 주자 1명당 약 60~90글자 → 9명이면 약 700자. 카톡 붙여넣기에는 문제 없음
- 릴레이 ID 표시: `#` + 16진수 4자리 (예: #A7F2)

### 7-3. 검증
- 접두어·버전·체크섬 확인 → 실패 시 구체적 오류 문구 (3-3)
- 값 범위 검사 (닉네임 길이, 점프 틱이 1800 넘지 않는지, 점프 수 상한 200)
- 닉네임은 화면에 넣을 때 반드시 텍스트로만 (`textContent`), HTML로 넣지 않기

### 7-4. 다시 달리기·덮어쓰기
- 결과 화면의 "다시 달리기"는 **받은 코드 기준**으로 다시 달림 → 새 기록이 내 슬롯을 대체
- 같은 사람이 같은 코드에 두 번 들어가는 것은 막지 않음 (닉네임으로만 구분되므로). 단, 완주 축하가 의미 없어지지 않게 "같은 닉네임이 이미 있어요" 안내만

## 8. iframe 안에서 살아남기 (대체 경로 필수)

| 기능 | 1순위 | 막혔을 때 |
|---|---|---|
| 복사 | `navigator.clipboard.writeText` | 숨긴 textarea 선택 + `document.execCommand('copy')` → 그래도 실패 시 코드 박스를 전체 선택 상태로 보여주고 "길게 눌러 복사하세요" |
| 붙여넣기 | `navigator.clipboard.readText` | 버튼 숨기고 입력칸에 직접 붙여넣기 |
| 공유 | `navigator.share` | 버튼 숨김 |
| 저장 | `localStorage` (try/catch로 감싸기) | 메모리에만 저장, 기능은 그대로 동작 |
| 소리 | Web Audio, 첫 탭에서 `resume()` | 소리 없이 진행 |
| 전체화면·화면 고정 | 사용하지 않음 | — |

- 외부 링크·새 창 열기 넣지 않기
- 모바일에서 화면 확대·스크롤·당겨서 새로고침 막기: `touch-action: none`(게임 영역), `user-select: none`, viewport `user-scalable=no`
- 길게 누를 때 뜨는 메뉴 막기: `contextmenu` 기본 동작 취소, `-webkit-touch-callout: none`

## 11. 코드 구조 (index.html 하나 안에서)

```
<style>  … UI 오버레이 스타일
<canvas id="game">
<div id="ui"> … 화면별 HTML (타이틀·코드 입력·결과 등)
<script>
  // 1. util     : PRNG(mulberry32), CRC16, LEB128, base64url, UTF-8
  // 2. constants: 물리값, 색, 패턴 조각 정의
  // 3. map      : generateMap(seed) → 장애물·별 목록
  // 4. sim      : createRun(map, inputs) / step(run, inputDown) / simulate(seed, inputs)
  // 5. bot      : botInputs(seed, skill) → inputs
  // 6. codec    : encodeRelay(relay) / decodeRelay(text) → {ok, relay | error}
  // 7. render   : 스프라이트 캐시, drawWorld, drawGhost, drawHUD, 이펙트
  // 8. audio    : sfx(name), bgm on/off
  // 9. storage  : safeGet / safeSet (try/catch)
  // 10. ui      : 화면 전환, 버튼, 복사·공유
  // 11. main    : 게임 루프, 입력 처리
  // 12. selftest: ?test 없이도 콘솔에서 runSelfTests() 호출 가능
</script>
```

- **1~6번은 DOM 없이 동작하는 순수 함수**로 → Node로 자동 테스트 가능하게 (개발 중엔 같은 코드를 테스트 스크립트에서 불러 쓰고, 출품 파일은 하나로 합침)
- 개발 저장소 구성 제안:
  - `src/` 에 나눠서 작성 → `build.js`가 하나의 `dist/ghost-relay.html`로 합침 (외부 의존성 없이 단순 문자열 합치기)
  - `test/` 에 Node 테스트
  - 출품 파일 = `dist/ghost-relay.html`

## 15. saaskr 업로드 폼 초안

- **게임 제목**: 고스트 릴레이 (HTML `<title>`도 동일하게)
- **한 줄 소개**: 친구의 유령과 함께 달리는 30초 릴레이 러너
- **장르**: 액션 (또는 아케이드)
- **플레이 기기**: PC·모바일
- **조작법**: 탭 또는 스페이스 = 점프, 길게 누르기 = 높이 점프
- **만든 도구**: Claude Code (실제로 쓴 것만 체크)
- **자세한 소개** (200자 이상):
```
목표: 30초 동안 장애물을 넘으며 최대한 멀리 달리고 별을 모으세요.
하는 법: 화면을 탭하면 점프, 길게 누르면 더 높이 뛰어요. 부딪혀도 죽지 않고 잠깐 멈칫해요.
재미 포인트: 한 판이 끝나면 내 플레이가 '유령'이 되어 도전 코드로 나와요. 친구가 코드를 넣으면 내 유령과 같은 맵을 함께 달리고, 친구의 유령도 쌓여요. 최대 10명이 이어 달리면 릴레이 완주! 유령과 같은 순간에 점프하면 '싱크' 보너스, 아무도 못 먹은 별을 먹으면 '구조' 보너스가 있어요. 오늘의 맵은 매일 바뀌어요.
만든 이유: 서버 없이도 친구와 함께 노는 느낌을 주고 싶었어요. 실시간이 아니어도, 친구의 실수와 묘기가 유령으로 남아 같이 달리는 장면을 만들고 싶었어요.
```
- **썸네일**: 유령 4~5명이 함께 달리며 "싱크!"가 뜬 플레이 화면 캡처
- **동의 체크**: 모든 그림·소리는 코드로 직접 만들었으므로 해당

## 16. 구현 세션에게 주는 작업 원칙

1. **시뮬레이션 결정성이 최우선.** 그리기·소리·UI는 시뮬레이션 상태를 읽기만 한다.
2. 작은 단계로 만들고, 단계마다 자동 테스트를 돌린 뒤 다음으로 간다 (14장 순서).
3. 실제 기기에서 확인할 수 없는 것은 "확인 못 함"으로 명확히 보고한다.
4. 숫자(물리값·점수)는 상수 한 곳에 모아 쉽게 조정할 수 있게 한다.
5. 외부 라이브러리·CDN·웹폰트를 쓰지 않는다.
6. 기능을 더하기보다 1차 출품 버전의 안정성을 우선한다.
